# Halted-RSP prefix experiment (#165)

Baseline: `19c9550516e3b86c24b40ceef17d847e4470c58a` (current `main` when the experiment started, 2026-10-10).
The issue's old `master` name now refers to `main`.

Recommendation: retain this as an experimental draft. The five-pair median
change is +0.74% for rendered GoldenEye stationary gameplay; all six Bun
headless windows have neutral or negative median paired changes (−0.05% to
−1.90%). This bounded prefix prototype does not establish a broad speedup.

Results and individual timing pairs are in [results/RESULTS.md](results/RESULTS.md).
Guard counts, code sizes, compilation costs and limitations are in
[results/DIAGNOSTICS.md](results/DIAGNOSTICS.md). Exact source and ROM hashes are
in [results/environment.json](results/environment.json).

## Bound and ordering contract

The prototype duplicates only the initial run of at least two audited register
or branch instructions. One `rsp.halted && !c.stuffToDo` guard selects the copy
without instruction-level RSP calls or interruption checks. The other copy
retains the original interleaving verbatim. All CPU instruction bodies, PC/delay
checks, exception bookkeeping, and return counts are retained.

The guard expires **before the first memory access, unknown helper, or
cycle-synchronizing bailout**, and specialization never resumes within that
fragment. Sync-flow tracing disables the specialization. These limits matter:

- Entry dispatch already bounds the entire fragment by the next queued event.
  An audited prefix cannot schedule/deliver an event, restart RSP, or request
  CPU interrupt service. A deadline inside the fragment forces interpretation.
- RSP cannot change from halted to active during that prefix. An active entry
  executes every original RSP step even if it halts partway through.
- Every memory operation, including an SP status write, executes through the
  original suffix. No cached halted state crosses that access.
- Branch and delay-slot work is never elided. Early exits return the original
  completed-instruction count; existing Count/Compare and RunForCycles accounting
  is unchanged. No cycles or necessary RSP instructions are skipped.
- Original profiling counters retain their meaning. Separate diagnostic runs
  count guard hits, actual step calls, halted calls, generated bytes and time in
  code generation/Function construction; those runs are not throughput evidence.

This is intentionally a smaller hypothesis than arbitrary multi-segment
specialization. The active-RSP idle executor, longer traces, RAM groups, audio,
TLB and FPU changes are outside this experiment.

## Reproduction

Install the pinned dependencies with `bun install --frozen-lockfile` in the
prototype checkout. Export baseline `19c9550` into a separate directory and link
or install its dependencies. Run CPU-heavy processes sequentially on an otherwise
idle host. Do not run tests, builds, profilers or another emulator during timing.

```sh
node tools/rsp_prefix/paired.mjs "$BASELINE" "$PROTOTYPE" /tmp/headless.json \
  '/Volumes/Data/Roms/Super Mario 64 (USA).v64' \
  '/Volumes/Data/Roms/Diddy Kong Racing (USA) (En,Fr) (Rev 1).z64' \
  '/Volumes/Data/Roms/GoldenEye 007 (USA).z64'
node tools/rsp_prefix/summarize.mjs /tmp/headless.json
```

Each of five adjacent pairs alternates baseline/prototype order, with a fresh
process for each sample. It invokes the existing headless harness, RSP execution
and default HLE audio enabled, graphics lists skipped, 600 measured VIs following
120 or 1320 warmup VIs (ending at VI 720 or 1920). This is startup/attract work,
not verified gameplay. The harness's GPR/PC fingerprint is only a diagnostic,
not the correctness oracle.

Build each checkout with `bun run build`, then run the rendered workload:

```sh
node tools/rsp_prefix/browser.mjs "$BASELINE" "$PROTOTYPE" \
  '/Volumes/Data/Roms/GoldenEye 007 (USA).z64' /tmp/rsp-prefix-browser 5
node tools/rsp_prefix/summarize.mjs /tmp/rsp-prefix-browser/browser.json
```

This uses Playwright 1.58.2 Chromium, fresh contexts, HLE graphics/audio, render
scale 1 and CRT off. RAF is disabled, CPU randomness uses the issue's seed and
LCG, and the exact input script from #165 drives rendered Dam gameplay. Loading
is measured separately over VIs 1660–2399; stationary gameplay is VIs 2595–3134.
The first pair saves comparable canvas screenshots to verify the scene. Rates
are VI/s, not game-rendered FPS. The ROM's big-endian SHA-256 is
`2cdcec8a9f0cb6e36337f3ee39d8ad105dc8afa6ba1c02d466e8f5b771f9a162`.

For separate diagnostics (temporary source copy, no production instrumentation):

```sh
bun tools/rsp_prefix/diagnostic.mjs "$BASELINE" "$ROM" /tmp/rsp-prefix-base 120
bun tools/rsp_prefix/diagnostic.mjs "$PROTOTYPE" "$ROM" /tmp/rsp-prefix-opt 120
bun tools/rsp_prefix/mmio_deadline.mjs "$BASELINE"
bun tools/rsp_prefix/mmio_deadline.mjs "$PROTOTYPE"
```

Diagnostic compilation time includes tracing/code generation and Function
construction, including the instrumentation's own bookkeeping. Source bytes are
measured before inserting diagnostic counters. The harness saves eight hot fragment sources; the checked-in report keeps a
representative idle and guarded body per game in each Bun variant. Browser
sources remain in the diagnostic JSON;
guard and step counts measure executed paths, not compiled-length estimates.

## Correctness checks

`recompiler_rsp_prefix.test.js` compares original compiled, specialized compiled
and interpreted execution in both profiling modes. It checks CPU GPR/COP0/FPU
state, PC/delay state, RAM, RSP scalar/vector/accumulator/control state, SP/MI
registers, event deadlines and cycle totals. Cases include halted/active RSP,
BREAK with and without interrupts, pending interrupts, SP restarts, SSTEP status,
events within the proposed prefix, non-NOP delay work, divergent branches,
delay-slot faults, short RunForCycles budgets and shortened Compare deadlines.
SSTEP coverage preserves current emulator behavior; it does not establish new
hardware single-step support.

The existing exception/timing suite supplies broader memory/FPU/exception
coverage. `mmio_deadline.mjs` explicitly reproduces #174's newly scheduled SP DMA
deadline bug separately; equality with the original compiler does not fix it.

The browser diagnostics use the same replay in a **separate, instrumented** run:

```sh
node tools/rsp_prefix/browser.mjs "$BASELINE" "$PROTOTYPE" \
  '/Volumes/Data/Roms/GoldenEye 007 (USA).z64' /tmp/rsp-prefix-browser-diagnostic 1 diagnostic
```

It retains every compilation's source and counters across invalidation, then
exports the eight hottest bodies. `completedCompiledOps` counts actual returned
prefix lengths and completed prefixes of thrown fragments; faulting instructions
are reported separately through `thrownFragments`, not treated as full trace
returns. The step wrapper counts halted calls separately from executed RSP
instructions. These instrumented wall times are deliberately excluded from the
paired timing table. Step counts do not measure RSP self-time or imply a
proportional throughput gain.

Validation: `bun test` (2,213 pass), `bun run lint`, `bun run build`, and Node
syntax checks for the measurement scripts.
