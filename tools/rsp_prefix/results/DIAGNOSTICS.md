The guard succeeds 11,362,608 / 12,223,848 times (**92.95%**). It removes 39,695,491 halted calls (9.68% of halted calls; 8.95% of all step calls). Useful RSP instruction count, completed compiled CPU instruction count, dispatch count and compilation count are unchanged.

Cumulative generated JavaScript source grows **4.88%** in the measured window. Across the full replay it grows 72,577,863 → 75,974,466 bytes (4.68%); Function construction takes 241.3 → 249.7 ms. Source bytes sum every newly compiled body; they are not resident machine-code size. Browser construction timing excludes code generation and later host-JIT optimization. This single diagnostic pair is not a statistical compilation benchmark.

This experiment does not cover active-RSP idle batching or later safe segments.

## Existing MMIO limitation (#174)

The retained MMIO diagnostic reports `SP_DMA_BUSY = 0` in the interpreter and `1` in both compiled versions after two NOPs, an 8-byte DMA start and a busy-register read. This reproduces the existing shortened-DMA-deadline bug in ordinary and profiled execution. Prefix specialization ends before the store and makes no additional halted-state assumption in the suffix. The discrepancy remains open; compiled-versus-compiled equality is not presented as interpreter correctness for this case.

## Decision

Retain the change as an experimental draft. It removes redundant halted calls with strong differential coverage, but the five-pair browser improvement is small and the six Bun windows have neutral or negative median paired changes. The added generated source and observed compilation costs are not justified by a dependable throughput improvement in this bounded prototype. Necessary RSP execution time was not isolated; instruction counts alone are not a host-time cost model.
